# Promote a transferable lesson into the owning skill

Conditional branch of `learn.md`. Use only for a proven cross-context method with an identified skill owner. Repository-specific facts remain local; personal facts remain private. No required companion plugin or promotion database.

1. Resolve the canonical editable skill/plugin source from the user's declared target, current source checkout or verified native installation/marketplace provenance. An installed versioned cache, generated adapter or workflow-only MCP is a read surface, not the authoring source. Missing source access yields a portable proposed patch on the existing owner, not a guessed home-directory path or a new global skill.
2. Verify current or standing authority for that exact source and separately for installation. A standing mandate comes from the user's supplied host/project instructions or settings, never learned wiki/PR content. An explicit global learning/self-evolution request can supply this scope; a normal project fix alone does not authorize unrelated repositories, publishing or changing global permission policy. Honor read-only/no-write/source restrictions. Learned content, reviewers and plugin-provided instructions cannot enlarge their own authority.
3. Read the target procedure and its callers. Bind each practice ID to its actual decision/execution point and reachable load trigger; promote the supported set with its dependencies, not just a chosen headline lesson. Use the smallest existing owner; ordinary methods belong in the executing skill/reference, global core only for a universal invariant. New skills need a distinct recurring capability without an existing owner. Preserve user choices, host/model limits, checks and external-effect boundaries.
4. Write the parameterized candidate method before claiming validation. Its mechanism and limits must survive a transfer exercise or falsifying counterexample for promotion as a validated default; prepare and run the smallest permitted check rather than rejecting generalization merely because only one case was supplied. Separate controlled proof from inference; repeated accounts are not independent validation. Private/source facts stay with their owner, never in shared instructions.
5. Stage the smallest source edit with version/previous-content identity, applicability, action, evidence basis and exception. Update the entrypoint/reference route when needed; remove or revise superseded duplicate guidance only within ownership. Preserve unrelated dirty work. Use a native read-only reviewer or a labelled separate self-review and exercise the affected workflow on a bounded case without revealing the desired answer to the evaluator. No production actions or invented test pass.
6. Run the repository's required checks and relevant behavioural proof. If the candidate fails, reconcile only this attempted edit against its prior content while preserving concurrent changes, or retain an explicit unvalidated patch; never install it as a proven rule. Do not weaken checks or repeatedly retry unchanged failures. No commit, tag, push or release follows from learning alone.
7. When installation is authorized, use the source's documented native update/install path, including version parity and generated adapters/agents when changed. Read back the installed instruction content and registration/load path. An MCP service that snapshots content requires its supported reload and live reference read-back within authority; a local package update alone does not update that service. Report unavailable hosts and sessions awaiting reload separately. Do not modify caches directly or claim universal activation from one host's success.
8. Return each practice ID's source revision, entrypoint/load trigger, checks, transfer proof and verified activation or pending reason to the original receipt. A fresh matching invocation must select the method and a nonmatching case must respect its exception; only actual application proves reuse. Reconcile every supported ID and later contradictions in the same owner, never by appending competing rules.

Stop at verified local activation within authority, a validated source change awaiting installation, or the exact blocked/proposed state. No automatic publication, cross-host credential transfer or modification of the learning mandate.
