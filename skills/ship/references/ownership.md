# Resolve declared code ownership

Read from dossier.md for every delivery's ownership check. This is read-only discovery, not authority to alter ownership, request reviews, mention people in messages or waive approvals.

1. Resolve the forge and the ownership policy revision independently of the diff base. For a PR/MR use the target-branch policy selected by that forge; on GitHub this is the current base-branch CODEOWNERS, which may differ from the merge-base. For a local delivery use the intended target when known; otherwise label the inspected revision and leave future approval requirements unassessed. Do not let a proposed HEAD ownership change silently replace the policy governing the current review.
2. Inspect only the supported locations and declared equivalents. GitHub selects the first existing file in .github/CODEOWNERS, CODEOWNERS, docs/CODEOWNERS order. GitLab selects CODEOWNERS, docs/CODEOWNERS, .gitlab/CODEOWNERS. Other forges use their native ownership/reviewer policies or the repository's declared convention; do not assume GitHub semantics. Record selected path and revision, or absence/unavailability once.
3. With local Git/Python on GitHub or GitLab, run `python3 <plugin root>/skills/ship/scripts/codeowners.py -C <repo> --forge <forge> --ref <governing-target-ref> --show`. It discovers the ordered policy at an exact commit, including hidden locations; it does not resolve path owners, syntax validity, eligibility or approvals. Use its selected path/text, not the first result of a file search. Without that capability, use native forge reads and explicitly verify location precedence/revision. Prefer native resolved ownership or an existing forge-compatible resolver. Apply that platform's matching semantics to changed paths and material affected consumers, including relevant old/new paths for renames. GitHub uses the last matching pattern, with multiple owners on the same line; its syntax is not full gitignore. GitLab sections and optional/required approval rules need GitLab semantics. A naive glob, basename match or single global last-match rule is not a portable resolver. An unresolved match stays unresolved; authors, commit history and folder names are not declared owners.
4. Group paths sharing an owner and reason. Return declared owner handles, affected scope and evidence locator; distinguish unowned paths, absent configuration, invalid rules and unread policy. Changes to CODEOWNERS get their own before/after impact and retain the current target-policy owner mapping. Keep materially affected external-domain owners separate from this repository's approvers.
5. Read actual required-review/approval state when assessing merge readiness. Refresh this receipt if the governing policy revision changes, even when the PR head stays unchanged. A declared owner, requested reviewer, eligible approver and satisfied approval are different facts. Ownership alone proves none of the others; unavailable policy is unassessed. Honor existing branch/ruleset gates. Do not manually request a review solely to fill the dossier, and render handles as code to avoid incidental mentions.

Report ownership once in the relevant domain row or a compact shared block; link the matching rule for drilldown. Do not repeat the same team against every mechanical file. Missing CODEOWNERS is a scoped observation, not an invented risk or reason to create one.

Primary references, recheck when platform behavior is uncertain:

- [GitHub code owners](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/customizing-your-repository/about-code-owners)
- [GitLab code owners](https://docs.gitlab.com/user/project/codeowners/)

Return ownership and approval facts/gaps to dossier.md. No external action follows from this lookup.
