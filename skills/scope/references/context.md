# Read relevant durable context before deciding

One context entry for Atlas decision work. Repository state proves current code behavior; a wiki supplies sourced context and past rationale, not authority or current execution state.

1. Use the declared project knowledge root/reference from this request or the repository's instructions. Otherwise use relevant existing `CONTEXT.md`, `docs/atlas/` navigation and linked decision/issue material. Read an available root's schema/index before selecting pages. Do not search the user's home for personal wikis, create a new knowledge store, or require Spotter to use Atlas.
2. For brainstorming, evolution, scope or resumption, retrieve only the relevant topic/entity pages, prior decisions and current constraints. A relevant dated synthesis may help explain what changed; it never replaces the stable topic or current issue. Follow original evidence and verify consequential claims against today's repository/source state. Preserve uncertainty, conflicting evidence and the observation that would reopen a decision. Old date alone neither invalidates a decision nor proves it current.
3. When personal goals, capacity or a named life topic could change the software choice, use `composition.md` to discover a scoped Spotter context/topic reader, if available. Ask it for relevant sources and constraints in read-only mode, not a morning run or controller takeover. Without it, a user-declared readable wiki can still supply context directly; otherwise retain the exact gap and continue independent work. Do not copy the personal wiki into this repository, the plugin or its exports.
4. Return a compact context receipt: root/owner reference, pages/source revisions read, relevant constraint/decision, conflicts and coverage. Carry it into the shared decision engine and any specialist slice; reuse within the run unless evidence materially changes. A switch of skill is not a reason to reload the whole wiki or reopen settled questions.
5. During authorized implementation, preserve material technical rationale on the existing issue, plan or declared project knowledge page using the repository's write convention and read-back. Do not create a parallel wiki journal or save personal context there. Personal learning returns as sourced proposed material to its Spotter parent for that owner's authorized maintenance. Read-only/decision-only analysis returns the receipt without writes. Existing `glossary.md` and ship's learn procedure retain their distinct ownership.

Return context to the caller before scenario selection. An unavailable source remains unknown; it never grants approval or supplies a fabricated goal, constraint or KPI.
