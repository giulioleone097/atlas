# Compose available skills around one outcome

Conditional coordination contract. Read when another skill's domain expertise or personal context can materially improve the requested software outcome. Return to the current caller; this is not another controller or a dependency on another plugin.

Before any dispatch, consult a slice receipt in the current turn or existing owner map: parent owner, capability, bounded child outcome, authority and the input revisions that defined the slice (not its produced outputs). An in-progress matching slice is awaited; a completed matching slice whose artifact/proof still matches is reused. Return that result to each caller without executing again. Record the returned receipt on the same owner, not a separate registry; only a changed input/authority, invalidated proof or disjoint outcome can justify another dispatch. A new entry skill alone cannot.

1. Keep one owner for the enclosing outcome, map, issue and native goal. Atlas owns the software slice: repository facts, implementation, technical proof and authorized delivery. A parent from another plugin retains its broader acceptance, priorities and state. A child result proves only its assigned slice.
2. Inspect the current host's supplied skill catalog, native skill tool or exposed workflow listing. Match a capability by its actual description and return contract, not a guessed command or an installed product name. Load only the relevant skill/reference, through a native invocation, a supplied readable path or its workflow MCP. A workflow loader provides instructions, not the execution tools those instructions may need. Do not install a plugin or scan unrelated workspaces to fill a gap.
3. Use the most specific compatible procedure already available. Repository questions stay in Atlas. A consequential personal preference, capacity constraint or topic may use Spotter's `context read`/topic view when exposed and within the user's context scope; resolve the selected wiki through that owner's contract. Other specialists can supply a bounded artifact or finding when their domain fits. Atlas still works from repository context and declared sources when no specialist exists; report only the actual missing evidence/capability.
4. Hand off one bounded request: parent owner/reference, child outcome and proof, selected source/page revisions, relevant constraints and unknowns, actual authorized actions, read-only/decision-only/evolution flags, and return destination. Include only context necessary for the slice. Personal wiki content stays out of distributable plugins and public repository artifacts unless explicitly authorized for that destination. Availability is not permission to read unrelated private data or to publish it.
5. Invoke the target now only if compatible with existing authority; otherwise retain its useful analysis or exact missing capability. The child returns evidence, artifact/reference, changed assumptions, proof, and unresolved questions to this owner. It cannot replace/finish the enclosing goal, create a mirrored backlog, widen a source window or re-run the parent's brainstorming.
6. Carry a compact visited owner/capability chain. Never hand the same unresolved request back to an ancestor controller; return the specific fact, probe or user decision instead. A changed or disjoint bounded slice may use another specialist. Reuse a current decision/review receipt instead of repeating the council. If the target is unavailable, incompatible or returns unchanged failure, continue the local supported route and independent work without retrying the same handoff.
7. Reconcile the returned evidence against this task's acceptance. Re-read consequential sources/artifacts, merge only affected decisions and record links on the existing map/issue. Technical findings do not decide personal values, and a life-planning priority does not prove software behavior. Use the shared asking procedure for the remaining human choice, never duplicate its pending panel.

Return the specialist evidence or explicit gap to the original workflow. No global skill registry, shared database, cross-plugin import, background loop or second execution owner is created.
