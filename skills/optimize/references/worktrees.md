# Isolate experiments and preserve their result

Owned by optimize. Use native Git worktrees and existing project setup; no simulator service, dependency or second task store.

1. Read Git status, index, revision, worktrees and selected ledger before mutation. Record starting revision and hashes/status of relevant tracked and task-owned untracked inputs. Editable paths and fixed benchmark/check inputs are distinct: workers never edit the latter to win. Resolve globs to explicit owned paths for staging and diffs.

2. A clean relevant source uses its current commit. For authorized uncommitted input, create an isolated snapshot with a temporary Git index (`GIT_INDEX_FILE`): seed it with the current commit, add relevant current files there, then `git write-tree` and `git commit-tree`. Preserve source index, branches and working files, including staging boundaries; never stash, reset or commit the user's checkout. Record snapshot identity and included paths. Exclude credentials and ignored artifacts from Git; supply authorized runtime inputs separately. If needed input cannot be reproduced safely, name that specific blocker.

3. An existing branch is resumable only with matching repository, ledger, mandate, source/snapshot, workload/setup and owned paths. Recover a missing working ledger from its retained ledger ref, verify its run identity, then reconcile candidate refs and any interrupted reservation/save. Reuse its champion, candidates and spent budget after verification. Changed inputs require rebaselining affected evidence, never calling old KPIs current. An unrelated or unverifiable branch stays untouched; choose a unique run name, or report missing provenance when explicitly asked to resume it. Do not reset another run or create a parallel owner for an active one.

The selected ledger has one versioned history, not a second task store. Before candidate dispatch, and after measurements/checkpoints, rounds and integration, persist its complete current contents in a generated `LEDGER` blob in a metadata-only Git commit using a temporary index or Git tree plumbing. Parent each snapshot to the previous ledger commit and retain it under a run-owned ref such as `refs/heads/optimize-ledger/<run-id>`. Validate ownership/names and advance with `git update-ref` using the expected previous SHA; a conflict is not overwritten. Read back the ref and `git show <ledger-sha>:LEDGER`, compare with the intended contents and return that SHA/ref as the persistence receipt. The working ledger is its readable copy; it contains checkpoint SHAs, lineage, measurements, reserved/spent budget and next action, but never its own commit SHA. Missing durable reservation blocks dispatch; any failed snapshot remains checkpoint-pending and blocks promotion/cleanup. No snapshot touches the source index/branch or includes secrets.

4. Put detached baseline/candidate worktrees under a task-owned temporary directory using `git worktree add --detach <dir> <exact base>`. Install/build through existing project setup. Every tree receives equivalent fixed inputs/environment. Start measured processes from that worktree with separate ports, data and caches where mutable state could leak; record identities and clean up only owned processes. A command against an existing shared server is not worktree proof: supply a checkout-local launcher within authority, otherwise report that blocker. Never point experimental writes at production or shared data.

5. Every verified gain gets a durable checkpoint before promotion, compounding or cleanup, including valid alternatives not selected as champion. Commit only explicit owned changed paths in that candidate's experiment tree, following repository conventions without agent attribution or bypassing hooks. Check the committed tree against the measured fingerprint; a hook/change that alters it requires remeasurement, not reuse of earlier numbers. Do not create empty gain commits for unchanged code or noise.

Create a retained lightweight local tag such as `refs/tags/optimize/<run-id>/<candidate-id>` pointing to the exact commit. Validate names through Git; reuse a matching ref, never force or overwrite a conflicting one. Advance only the run-owned `optimize/<slug>` champion branch after its checkpoint is complete; other valid gains keep their own refs. All measurement records stay in the existing ledger outside candidate edits: checkpoint SHA/ref, parent/components, source/setup and measured-tree fingerprints, control/candidate values and noise, guards/checks, status and remaining budget.

Read back the commit, changed paths, ref target and the step-3 ledger snapshot containing that checkpoint before declaring the gain saved; return the ledger SHA/ref alongside the checkpoint receipt. Commit/ref/write failure remains `checkpoint-pending`; preserve the worktree and exact next step, do not advance the round or integrate. Resume reconciles existing commits/refs before retrying, so a partial save creates no duplicate checkpoint. Keep earlier refs through rebaselining; changed source inputs may create a new continuation lineage, never rewrite old checkpoint history or reset its budget. No checkpoint operation stages, commits or rewinds the user's source branch.

6. Before landing reread source HEAD, relevant files and staging state. Generate the diff from recorded snapshot to champion, restricted to owned paths. Preflight with `git apply --check`; a three-dot diff against moving HEAD does not prove source compatibility. If relevant source/runtime inputs changed, reconcile the champion on a fresh snapshot without overwriting user edits, and remeasure fresh control and candidate before landing. A conflict blocks integration only: retain champion, patches and exact resume step.

7. Apply the checked task patch without changing the user's index; record exactly what this run integrated. Run final metric, guards, regression and review. If review/integration repairs change the verified result, capture the repaired owned tree in the isolated experiment history, remeasure it against the current control, and save another checkpoint by step 5. The final ledger must identify the tree actually delivered. On failure retain recovery and repair or preflight reversing only this run's patch while source files still match it; otherwise reconcile concurrent changes. Never use whole-tree restore/reset.

8. After final proof and durable ledger read-back, remove only disposable worktrees/processes that no recovery needs. Keep the run branch, checkpoint refs, ledger ref and their reachable commits as the optimization history; normal completion never deletes, squashes or rewinds them. Cleanup of that history requires an explicit user request. No refs/tags are pushed automatically. Missing persistence remains explicit, never a claim that the run can resume from a saved gain.

Return root/champion identities, source comparison, owned worktrees/processes, checked integration and recovery status. Stop when the caller's requested setup, resume or integration operation has been verified.
