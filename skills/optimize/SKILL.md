---
name: optimize
description: Use when improving measurable performance, resource use or quality. Test isolated alternatives, checkpoint every verified gain in Git and compound improvements within one budget.
argument-hint: "<outcome> [overrides: --metric <command> --higher --target <n> --guard <command> <max> --paths <globs> --rounds <n> --parallel <k> --out <file> --no-review]"
---

1. Bind outcome, acceptance, authority and explicit constraints through core's Intent rule and `<plugin root>/skills/build/references/agency.md` (`<plugin root>` is the parent of `skills/`). Read-only, decision-only and card-only requests return the design without mutations or workers. A requested continuous run or active native owner uses `<plugin root>/skills/build/references/native.md` before experiments; reuse its owner and never create a second goal. An authorized optimization includes local experiment checkpoint commits, not commits on the user's source branch or publication. Explicit no-commit/read-only limits win: return design or permitted measurements labelled uncheckpointed, without promotion or integration. Retain the caller's map/owner; missing technical flags initiate discovery, not configuration questions.

2. Resolve the KPI contract through `<this skill>/references/metrics.md` (`<this skill>` is this file's directory): recommend relevant metrics from presets, outcome, code and available evidence; use the native asking contract for an unsettled priority. Reuse explicit or still-valid user-selected KPIs and targets. The agent selects commands, direction, owned paths, checks and setup within that contract. A metric command must exit successfully and end with one finite number; prefer an existing benchmark or minimal wrapper over representative work, with fixed inputs/checks. `--metric` overrides the command. Each guard also returns a finite number and has a maximum, absolute or `+N%` of its original baseline; non-numeric correctness remains mandatory. Diagnose and repair a failed supplied command's setup; changing its meaning requires resolution, never a silent substitute.

3. Choose bounded options. Defaults are up to six rounds and three candidate slots per round, reduced for scope, runtime and available resources; explicit `--rounds`/`--parallel` and other limits win. Record initial slot width and root candidate limit (rounds times width, capped by any inherited or explicit allowance) once; singles, combinations and failed attempts consume it. Inherited work uses only the remaining allowance and returns actual consumption, never a fresh budget. Actual concurrent workers may be fewer under contention without changing that limit. Never invent time/token allowances. Record consequential selections with `explicit|saved|inferred` provenance and evidence. `--out` selects the ledger, otherwise `docs/optimize-<yyyy-mm-dd>-<slug>.md` in the target project; a parent map links this single experiment record.

4. Establish or resume isolated state through `<this skill>/references/worktrees.md` (`<this skill>` is this file's directory). Inspect a dirty checkout or existing run instead of automatically rejecting it. Lock exact starting revision, input/setup fingerprints, source state and ownership. Run the metric three times in the baseline worktree and every guard/check; median is baseline and spread is noise, at least the smallest reported unit. If spread exceeds one fifth of target distance (baseline magnitude without a target), raise runs to five, then seven within real limits. Persist the run count. Persistent noise leaves gains unproven; never accept inside the band. Attribute baseline check failures before proceeding; they never count as passing coverage.

5. Profile the champion when a profiler exists; otherwise use code evidence and label that basis. For an evidenced latency, payload, eager-dependency or graph-computation constraint, read `<this skill>/references/replicate.md` and fill the matching recipe's parameters, operations and guards. List materially different alternatives with mechanism, KPI, parent/base, scope and falsifying observation; include supplied options and a control. Each gets measured, rejected-with-evidence, blocked or deferred status. Prioritize useful evidence over filling slots; repeated candidates need changed inputs or a new mechanism. Keep identities on the same ledger.

6. Reserve candidate IDs and spent/remaining allowance on the existing ledger and read back its durable Git snapshot through worktrees.md before dispatch; interrupted reservations never reset the budget. Implement candidates in separate worktrees from this round's same saved champion SHA. Give workers hypothesis, owned paths, fixed workload/setup, checks and one smoke measurement, preserving model pins. Without optional delegation, execute sequentially with the same isolation and disclose it. Workers never integrate into the source checkout; their numbers are smoke results, not verdicts. Before measurement inspect ownership, workload/check integrity and mechanism. A shorter benchmark, fewer samples, disabled guard or reduced supported behavior is a discard.

7. After workers and processes stop, remeasure control and candidates serially with the fixed setup, run count, guards and checks. Require improvement beyond both spreads and metric resolution; absolute guards stay anchored to the original contract. Failures, invalid output, regressions or guard violations reject the candidate. Before promotion or another round, checkpoint every valid measured gain, including useful non-winning candidates, through worktrees.md's checkpoint protocol. Commit, retained ref and ledger read-back are one required gate; a failure remains checkpoint-pending with recovery intact. Choose at most one saved champion per round and retain other saved gains for recombination. Record values, noise, incremental/root delta and reasons. Rebaselining preserves history and budgets; incomparable root deltas stay unavailable.

8. Compound after a keep: make evidence-backed combinations part of the next candidate batch. Reapply a useful runner-up or combine complementary mechanisms on the current champion, then measure the whole result by step 7. Disjoint paths do not prove independence; overlapping paths are allowed after reconciling actual interactions within ownership. A neutral/rejected idea returns only with a specific new synergy hypothesis or changed prerequisite. Never blindly merge patches, add individual deltas or assume a former win survives a changed base. Every combination records component IDs, actual parent revision and interaction hypothesis, consuming the same root budget. Prefer the smallest decisive combination; no exhaustive Cartesian search or recursive budget reset.

9. Persist and read back each round's ledger with contract, root/champion SHAs, every gain's checkpoint SHA/ref, input fingerprints, spent/remaining allowance, lineage, measurements, status and next action. Reuse matching checkpoints on resume; never recommit the same measured tree or lose earlier gains during rebaselining. Stop at target, real bounds, two dry rounds without a supported new mechanism/combination, no informative candidate, or a checkpoint blocker. Report untested options and pending saves; failure or noise never becomes a gain.

10. Land only a saved verified champion through worktrees.md. Remeasure control and integrated source serially, then run public `<plugin root>/skills/review/SKILL.md` unless `--no-review` or no keep. A review/integration repair invalidates affected evidence: recheck metric/guards/regression against fresh control and checkpoint the verified repaired tree in the experiment history before calling it final. Keep recovery until proof succeeds; on failure repair or safely reverse only this run's integration. Retain all gain commits and refs after temporary-worktree cleanup. No source-branch commit, push, tag publication or release is implied.

11. After a verified result, pass the existing ledger, controls, saved alternatives and final checks to `<plugin root>/skills/ship/references/learn.md`. Its reverse analysis identifies which optimization/development practices contributed and their limits, then internalizes supported lessons within existing authority. Reuse its receipt at later build/ship boundaries; no repeated benchmark, second ledger or implicit source commit.

Return verified evidence to the enclosing workflow, which retains parent acceptance. Stop when bounded search, integration/recovery, review and required remeasurement are complete or a concrete blocker remains. Never widen paths or authority to reach a target.
