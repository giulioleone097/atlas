---
name: optimize
description: Use when improving measurable performance, resource use or quality. Recommend relevant KPIs, settle priorities with native questions, test alternatives in isolated worktrees and compound verified improvements within one budget.
argument-hint: "<outcome> [overrides: --metric <command> --higher --target <n> --guard <command> <max> --paths <globs> --rounds <n> --parallel <k> --out <file> --no-review]"
---

1. Bind outcome, acceptance, authority and explicit constraints through core's Intent rule and `<plugin root>/skills/build/references/agency.md` (`<plugin root>` is the parent of `skills/`). Read-only, decision-only and card-only requests return the experiment design without mutations or workers. Retain the caller's map/owner and options; return evidence there, never call an ancestor. Missing technical flags initiate discovery, not configuration questions.

2. Resolve the KPI contract through `<this skill>/references/metrics.md` (`<this skill>` is this file's directory): recommend relevant metrics from presets, outcome, code and available evidence; use the native asking contract for an unsettled priority. Reuse explicit or still-valid user-selected KPIs and targets. The agent selects commands, direction, owned paths, checks and setup within that contract. A metric command must exit successfully and end with one finite number; prefer an existing benchmark or minimal wrapper over representative work, with fixed inputs/checks. `--metric` overrides the command. Each guard also returns a finite number and has a maximum, absolute or `+N%` of its original baseline; non-numeric correctness remains mandatory. Diagnose and repair a failed supplied command's setup; changing its meaning requires resolution, never a silent substitute.

3. Choose bounded options. Defaults are up to six rounds and three candidate slots per round, reduced for scope, runtime and available resources; explicit `--rounds`/`--parallel` and other limits win. Record initial slot width and root candidate limit (rounds times width, capped by any inherited or explicit allowance) once; singles, combinations and failed attempts consume it. Inherited work uses only the remaining allowance and returns actual consumption, never a fresh budget. Actual concurrent workers may be fewer under contention without changing that limit. Never invent time/token allowances. Record consequential selections with `explicit|saved|inferred` provenance and evidence. `--out` selects the ledger, otherwise `docs/optimize-<yyyy-mm-dd>-<slug>.md` in the target project; a parent map links this single experiment record.

4. Establish or resume isolated state through `<this skill>/references/worktrees.md` (`<this skill>` is this file's directory). Inspect a dirty checkout or existing run instead of automatically rejecting it. Lock exact starting revision, input/setup fingerprints, source state and ownership. Run the metric three times in the baseline worktree and every guard/check; median is baseline and spread is noise, at least the smallest reported unit. If spread exceeds one fifth of target distance (baseline magnitude without a target), raise runs to five, then seven within real limits. Persist the run count. Persistent noise leaves gains unproven; never accept inside the band. Attribute baseline check failures before proceeding; they never count as passing coverage.

5. Profile the champion when a profiler exists; otherwise use code evidence and label that basis. List materially different feasible alternatives, their mechanism, relevant KPI, exact parent/base, change scope and falsifying observation. Include caller-supplied options and a baseline control. Each named alternative eventually has measured, rejected-with-evidence, blocked or deferred-by-budget status; never claim exhaustive coverage. Prioritize bottleneck evidence and useful information over filling slots. A repeated candidate needs changed inputs or a new mechanism. Keep candidates and patch/revision identities in the same ledger.

6. Implement each selected candidate in its own worktree from the same exact champion revision for this round. Give bounded native workers the hypothesis, owned paths, fixed workload/setup, checks and one smoke measurement; resolve available models without overriding explicit pins. If delegation is unavailable, execute sequentially with the same isolation and disclose it. Workers preserve others' edits and never integrate into the source checkout. Their numbers are smoke results, not verdicts. Before measurement inspect ownership, workload/check integrity and mechanism. A shorter benchmark, fewer samples, disabled guard or reduced supported behavior is a discard.

7. After workers and their processes stop, remeasure champion control and candidates serially under the same setup, with the baseline run count, guards and regression checks. Compare each median with this round's champion; require improvement greater than both observed spreads and the metric's resolution. Absolute guard limits remain anchored to the original contract, never ratchet per round. Failures, invalid output, behavior regressions or guard violations reject a candidate. Rank only valid measured improvements; retain at most one champion per round and the others as reusable evidence. Record values, noise, incremental delta and root delta when inputs remain comparable, not just the winner. After changed source inputs require rebaselining, report the new control separately and mark incomparable root deltas unavailable.

8. Compound after a keep: make evidence-backed combinations part of the next candidate batch. Reapply a useful runner-up or combine complementary mechanisms on the current champion, then measure the whole result by step 7. Disjoint paths do not prove independence; overlapping paths are allowed after reconciling actual interactions within ownership. A neutral/rejected idea returns only with a specific new synergy hypothesis or changed prerequisite. Never blindly merge patches, add individual deltas or assume a former win survives a changed base. Every combination records component IDs, actual parent revision and interaction hypothesis, consuming the same root budget. Prefer the smallest decisive combination; no exhaustive Cartesian search or recursive budget reset.

9. Keep the winner as a local experiment commit in its worktree and owned run branch, preserving patches and source snapshot per worktrees.md. Persist and read back the ledger after each round: contract/provenance, root/champion identities, inputs, spent/remaining budget, lineage, measurements, statuses/reasons and exact continuation. Reuse unchanged completed results; source/setup drift invalidates dependent evidence only. Stop at an explicit target, spent round/candidate/resource bound, two dry rounds with no remaining supported combination or new mechanism, or no informative candidate. Report untested options and why; failure or noise never becomes a gain.

10. Land only a verified champion through worktrees.md's checked integration. Remeasure retained control and integrated source in the same serial pass, with fixed metric, guards and checks, then invoke public `<plugin root>/skills/review/SKILL.md` unless `--no-review` or nothing was kept. Any review repair reruns affected regression checks, metric and guards against a fresh control; retain proof only if the complete result still beats control beyond noise. Keep recovery state until final proof succeeds. If it fails, repair within scope or safely remove only this run's integration; report failure and recovery location. Never erase concurrent work or delete the only surviving champion. No source commit, push or release is implied.

```
options: <KPI recommendation/selection, unit/direction, command, paths, guards, limits; explicit|saved|inferred and evidence>
kpi: control <median> (spread <n>) -> final <median>, delta <n>; root delta <n/percent|undefined for zero baseline|unavailable after rebaseline>, target <met|gap|none>
kpi: rounds <n>/<limit>, candidates <n>/<limit>, combinations <n>, kept <n>, rejected <n>, deferred <n>, wall <observed minutes>
kpi: regression <command> - pass|baseline failure|new failure|unavailable
kpi: guard <command> <root> -> <final> (fixed max <n>) - held|broken
candidate <id>: parent <revision>; components <ids|single>; <metric/noise/delta>; <kept|rejected|blocked|deferred: reason>
profile: <observed bottleneck|code evidence>
stopped: <target|bounds|no informative candidate|dry rounds|blocker>; untested: <ids/reasons|none>
integration: <verified|not applied|failed>; recovery: <retained state|cleaned after proof>
ledger: <path; saved and read back|unsaved: reason>
```

Return verified evidence to the enclosing workflow, which retains parent acceptance. Stop when bounded search, integration/recovery, review and required remeasurement are complete or a concrete blocker remains. Never widen paths or authority to reach a target.
