# Deliver an operational reuse kit

Public reverse transfers working solutions to a new agent without repeating the original investigation. Analysis supports the kit; automatic learning updates its existing owner only for changed evidence/assets.

1. Recover the actual implementations, commands, configurations, fixtures and checks behind every material practice. Inspect source, callers and dependencies at a verified revision. Prefer an existing callable/exported owner; otherwise deliver a bounded snapshot or exact extraction/adaptation. A path, technique name, pseudocode or invented abstraction alone does not transfer an available implementation. Copy the smallest coherent unit with its essential dependencies, not the whole application.
2. Each asset names its practice ID, source/revision, entrypoint, dependencies, inputs/outputs and mode: **use directly**, **adapt specified seams**, or **reference only** with the exact gap. Keep private code/facts in their authorized owner, never distributed skills. A generalized extraction is a new artifact with its own proof status; preserve original provenance.
3. Specify **USE** (exact import/call/file/command), **ADAPT** (parameters and target integration points), **KEEP** (invariants and unchanged implementation), and **VERIFY** (focused integration check and expected result). Include a concrete invocation or filled example. Bind each new target requirement, including implied compatibility needs, to its asset seam, source evidence and pass/fail/unknown check; original-case parameters are not an exhaustive target contract. Preserve scope, invalidation, lifetime, errors, authorization and ordering wherever the asset relies on them.
4. Compose assets in execution order: observable selection conditions, necessary bundles, exclusions, failed alternatives and rollback. Explain how to replace case constants without promising historical gains. Keep practice IDs unchanged across analysis, kit and adoption; use distinct asset identifiers that link back to them. Map every material practice to an asset or actionable gap, preserving causal uncertainty.
5. Lead with a ready-to-use **agent brief**: outcome; kit location; inputs to resolve from the new task; exact assets/integration steps; invariants; acceptance commands/observations; deliverable. Start from the supplied implementation and investigate only target mismatches or failed checks. An applicable proven solution is the default; redesign needs a concrete incompatibility or demonstrated better equivalent. Report assets actually reused and adaptations made.
6. Separate proven-in-source, extraction-checked, compatible-with-target and applied-in-target. Reuse historical mechanism evidence; check new dependencies/contracts and any claimed target benefit without repeating the discovery campaign. Missing transfer proof limits generalized validation, not delivery of an existing solution or conditional adaptation. Never fabricate transfer success.
7. Check adoption after delivery. Original case code proves case implementation. Future adoption needs a reachable owner supplying the actual asset and equivalent applicability, parameter selection, operations, checks and exceptions. Link the kit from the existing project/context or skill entrypoint within authority. Generic reuse/measurement guidance and detached analysis are insufficient; unchanged adoption still returns the kit.
8. Deliver the brief and assets in the user's language first, then source-bound drilldown, coverage, uncertainties and adoption. Save/update one kit on the existing documentation/outcome owner within authority; absent an owner, explicit reverse may use one named artifact in the current workspace. Read-only/unavailable persistence receives operational content in chat, marked unsaved. Avoid duplicate ledgers and redundant files.
9. Exercise a fresh consumer using only the kit and a different concrete input: locate source, bind parameters, reuse an asset through its real entrypoint and run its focused check when permitted. Enforce an exclusion too. Prefer an independent reader; label self-review or unavailable execution accurately. A proposed plan or agreement is not application proof. Repair missing assets, dependencies or unsafe adaptations before claiming executability.

A compact brief can use:

```text
Outcome / target inputs: ...
Read kit: ...
USE: <asset@revision -> exact entrypoint/call>
ADAPT: <target requirement -> seam/change -> evidence -> pass/fail/unknown>
KEEP: <behavior/invariants/essential dependencies>
VERIFY: <command or observation -> expected result>
Deliver: <integrated result + reused assets/adaptations + proof/gaps>
```

Stop after kit delivery/read-back and truthful asset, usability and adoption states. Analysis, a recipe-only playbook, a source inventory or "nothing new to learn" alone does not satisfy reverse. No new optimization, commit or release is authorized here.
