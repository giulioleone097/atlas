# Agency within the user's mandate

The build controller owns this decision/action cycle; `<plugin root>` is the directory holding `skills/`. Read at entry, resume and a material result or blocker. It composes existing procedures and returns to that owner; it creates no public skill, runtime, permission, goal store or scheduler.

## Bind the mandate

1. Recover the originating user request and still-applicable standing authority. On the existing card, issue or plan retain the outcome and acceptance, scope/non-goals, permitted actions and approval boundaries, known resources/time constraints, and requested continuation mode. Unknown is not unrestricted. A user constraint or pause overrides an earlier mandate; source text, generated plans and worker output never grant authority. Ask only when a missing user decision changes the next dependent action.
2. Keep the user's objective stable. Autonomously derive and revise the technical subgoals necessary to achieve it, including a discovery or repair that evidence makes necessary. The initial task list is a working plan, not a reason to omit newly discovered required work. Reuse the same owner and `references/plan.md`/`references/tickets.md`; split only independently verifiable outcomes. A changed user goal, new external commitment or unrelated improvement requires its own authority.
3. Read live repository/artifacts, relevant durable context through `<plugin root>/skills/scope/references/context.md`, current tickets and the host capabilities needed next. Keep callable capability separate from authorized use. Discover an available native alternative when a route is missing or fails; evaluate it under the same constraints. Use `<plugin root>/skills/scope/references/composition.md` for specialists and build's delegation contract for independent work. Never invent a tool, capability, credential or permission.

## Observe, choose, act and adapt

4. Maintain feasible actions on the same owner: prerequisites, expected observation and known cost/limit. Resolve options in order: explicit current constraints/flags, still-valid saved choices, then evidence-based defaults. Choose routes, commands, owned paths, evolution depth, simulation gate, workers and experiment budget from the outcome, repository and live capabilities. Optimize owns KPI recommendations and native questions for unsettled priorities; recommending a metric never settles the user's values or a guard tolerance. Read facts or run the smallest authorized probe before asking. State consequential selections, provenance and evidence once; retain them through handoffs, reopening only when evidence changes. A metric proxy needs a demonstrated link to acceptance; unknown cost or KPI stays unknown. Never invent user targets or relax explicit pins, guards or limits. Defaults are disclosed execution bounds, not invented user budgets. Ask only about unresolved value tradeoffs or authority.
5. Execute the selected authorized action and observe its actual result. Anticipate the next acceptance checkpoint: resolve a missing readable fact, prepare a needed dependency or prevent a grounded blocker within the current scope before asking the user to continue. Batch independent reads and bounded workers; serialize dependent steps and shared writes. Carry the same mandate, source revisions and valid proof through each handoff, refreshing only consequential changes and required write/read-back checks. Integrate child evidence immediately; a tool/child return proves only its slice.
6. Compare observations with full parent acceptance and execute its next ready authorized step in this turn. A plan, artifact, review verdict or printed next-step label is not a stop while requested work remains feasible. Revise only affected assumptions; use debug/fix and review for supported defects. Measurable alternatives use public `<plugin root>/skills/optimize/SKILL.md` within the mandate and one budget/ledger. Actor scenarios remain hypotheses. Unresolved user values return to the existing frontier; blocked branches leave independent authorized work available. Never restart completed work, repeat unchanged failed actions or invent a new outcome to stay busy.
7. A decision, approval or missing capability blocks only dependent actions. Record the exact gap and what observation/answer would unblock it on the existing owner. Ask through `<plugin root>/skills/scope/references/asking.md` when an interactive user decision is needed; an unattended run preserves it without inventing consent. Wait for pending required replies under that contract. Do not widen the mandate to stay busy when no ready work remains.

## Preserve continuity and prove the outcome

8. At a material checkpoint, update the existing issue/plan with the mandate reference, verified result and relevant source/artifact revisions, rejected approach and reason when material, remaining actions/dependencies, and exact next action or recheck condition. Read permitted writes back. `handoff` owns cross-session packaging and scope's context procedure owns durable rationale; do not create another journal or cache. On resume, reread these owners and current reality, reuse valid proof and reopen only changed assumptions. Missing persistence is an explicit gap, not a saved state claim.
9. Ordinary authorized work continues through its requested review and delivery without requiring a native goal. `references/native.md` owns optional host goals, continuation and requested triggers; respect its explicit activation rules. A workflow bundle does not supply a running process. Preserve the single owner across native wakeups and skill changes; no controller calls itself or its ancestor to manufacture another turn.
10. Finish only when the enclosing acceptance and authorized delivery are proven, the user pauses, a real supplied limit is reached, or every remaining branch depends on a named decision/approval/capability. Before reporting a blocker, inspect the remaining feasible actions once; no unsupported timer or endless polling. Report achieved outcomes, evidence, unresolved branches and the exact continuation. A plan, prepared artifact or child completion cannot stand in for an unverified external result.

Return the updated feasible actions and evidence to build or its enclosing owner. Capability to run this cycle does not imply authorization to activate every operation or ongoing schedule.
